# Проєктування автономних мереж — практичні роботи

Один студентський Git-проєкт для ПР3–7. У ньому ви поступово створюєте контейнерний мережевий стенд: від першого Dockerfile до сегментації, моніторингу, резервування та локальної AI-діагностики. Репозиторій містить протоколи, заготовки з правильними назвами й автотести. Конфігурації заповнюєте самостійно за завданнями.

## З чого почати

Відкрийте [ПР3 — встановлення середовища й початок проєкту](docs/pr03.md#p-01-встановлення-й-власний-git-репозиторій). Це покроковий маршрут з нуля: підготовка середовища для вашої ОС, встановлення Git і Docker, перевірка готовності, власна копія репозиторію, перша конфігурація та автотест.

Основний Windows-маршрут у ПР3: Ubuntu WSL2 → Git в Ubuntu → Docker Desktop і WSL Integration. Там само описано альтернативу з Git Bash, macOS та Linux/VM. Оберіть свій маршрут і продовжуйте роботи в одній власній копії. Конкретне посилання на викладацький шаблон надає викладач.

## Навігація за роботами

| Робота | Протокол | Що додається до проєкту |
|---|---|---|
| ПР3 | [Git-проєкт і контейнерне середовище](docs/pr03.md) | Установлені інструменти, власний репозиторій, Dockerfile та базовий Compose |
| ПР4 | [Віртуальна мережа й доступ](docs/pr04.md) | Мережа «працівник — гість — сервіс» і перевірена матриця зв’язності |
| ПР5 | [Базовий моніторинг](docs/pr05.md) | Prometheus, Blackbox Exporter та перевірки цілей |
| ПР6 | [Відмовостійкість і сповіщення](docs/pr06.md) | Резервний сервіс, правила сповіщень та дослід відмови/відновлення |
| ПР7 | [Візуалізація й локальна AI-діагностика](docs/pr07.md) | Grafana, локальна Ollama та аналіз контрольованого інциденту |

Кожна наступна робота продовжує попередню. Початкові TODO-файли заповнюються у відповідній практичній; майбутні етапи не потрібно розгортати наперед.

## Що лежить у репозиторії

| Шлях | Призначення |
|---|---|
| docs/pr03.md–pr07.md | Завдання, покрокові команди, очікувані результати, діагностика та здача |
| docs/git.md | Додаткові пояснення Git, власного remote, commit і тегів |
| docs/commands.md | Значення команд, параметрів і фіксованих імен стенда |
| docs/platforms.md | Довідник альтернативних середовищ і доступу до панелей |
| Dockerfile | Заготовка власного навчального образу |
| compose.yaml та compose.*.yaml | Заготовки конфігурацій етапів стенда |
| config/ і site/ | Конфігурації та файли навчальних сервісів |
| tests/ | Надані автоперевірки та допоміжні компоненти |
| tests/images.lock.json | Перевірені образи й очікувані digest |
| .env.example | Спільні параметри, з яких у ПР3 створюється локальний .env |
| .gitlab-ci.yml | Конфігурація додаткової автоматизації GitLab CI |

Під час виконання тестів з’являються `docs/reports/prNN.md` — автоматичні протоколи для Git — і `results/` з докладними машинними результатами та журналами. Окрема папка ручних reports/ не потрібна.

## Автоперевірки

ПР3–6 оцінюються автоматично по 10 балів, ПР7 — на 12 балів. Правила, необхідні передумови й команди повної перевірки наведені в кожній практичній. Локальний звіт є самоперевіркою; офіційний автоматичний результат потребує контрольованого викладачем запуску.

Додаткову автоматизацію GitLab задає .gitlab-ci.yml; для виконання потрібний сумісний runner із Docker. GitHub не виконує цей файл. CI без локальної моделі не підтверджує повне виконання ПР7: обмежений запуск має частковий результат. Деталі виконання наведені в протоколах.

## Здача робіт

Для здачі потрібен **тільки URL власного GitHub/GitLab-репозиторію**. У ньому мають бути конфігурації, тег етапу й автоматичний Markdown-протокол. Докладні кроки збереження версії та надсилання є в протоколі роботи.

`.env`, сирі результати, журнали, кеші та ваги моделей залишаються локальними. Не додавайте їх до Git. Сервіси стенда належать одній Compose-групі `autonomous-netlab`; запуск, зупинка й відновлення описані у відповідній практичній.
